# Module 00 - Encapsulation / S6: findOrThrow の切り出し・iterator と const_iterator（2026-11-09）

## やったこと
- `deleteAccount` を `find` → `end()` 判定 → `delete it->second` → `erase(it)` に書き直した
- `find` + `end()` 判定 + `throw` の重複を private ヘルパー `findOrThrow` に切り出した。iterator 版と const_iterator 版の2本
  - `operator[] const` → const 版を使って `return *(findOrThrow(id)->second);`
  - `deleteAccount` / `deposit` / `withdraw` → iterator 版
- `deposit` / `withdraw` が `clientAccounts[id]` を経由しなくなった。存在しない id で `NULL` が挿入されて落ちる穴が閉じた
- `public:` を `class` と同じ桁に移した
- コンパイルエラーは残り2系統（下の「残っている」参照）。今回直した範囲からは新しいエラーは出ていない

## 疑問→理解のラリー

### `public:` のインデント幅
- 疑問: C++ の常識ではどのくらいなのか
- 理解: 決まった正解はなく流派が3つ。`class` と同じ桁（LLVM、Qt、42 の多くのコード）、半段下げ（Google は1スペース）、メンバと同じ桁
  - アクセス指定子は文ではなく「ここから区分が変わる」ラベル。メンバと同じ高さだと区切りとして目に入らないので、`class` と同じ桁にする

### `deleteAccount` と `operator[]` の重複
- 疑問: `operator[]` と `find` → `end()` 判定の部分が被る。`operator[]` を使い回せないか
- 理解: `operator[]` は参照を返し、`erase` はイテレータを要求する。使い回しではなく**重複している部分だけを private ヘルパーに切り出す**
  - `deposit` / `withdraw` の `clientAccounts[id]` は **map の `operator[]`** であって Bank の `operator[]` ではない。別物を混同していた
  - 「見つからなければ例外」というルールを1か所に集めると、将来エラーの扱いを変える時も1か所で済む

### iterator と const_iterator の違い・const はどこに付くか
- 疑問: ヘルパーはどちらを返すべきか。const_iterator は「`++` はできるが key や second は変えられない」くらいの理解で、`delete` する `deleteAccount` では使えない気がした
- 理解: `const_iterator` の const は**イテレータ自身ではなく指している要素**に付く。`*cit` の型が `const std::pair<const size_t, Account*>&` になる、と考えると全部説明できる
  - `-std=c++98` で実験した結果

    | 操作 | const_iterator で | 理由 |
    |---|---|---|
    | `++cit` | できる | イテレータ自身は const ではない |
    | `cit->first = 5` | できない | map の key は iterator でも常に const（`pair<const size_t, ...>`） |
    | `cit->second = NULL` | できない | pair が const なので `Account*` が `Account* const` になる |
    | `cit->second->value = 1` | **できる** | const はポインタの値まで。指し先の Account には付かない |
    | `delete cit->second` | **できる** | delete は const ポインタからでも合法 |
    | `m.erase(cit)` | **できない** | C++98 の `erase` は `erase(iterator)` のみ。const_iterator 版は C++11 から |
    | `const_iterator c = it` | できる | iterator → const_iterator の暗黙変換はある |
    | `iterator i = cit` | できない | 逆は無い |

  - second が指す Account の中身は const_iterator でも変えられてしまう。11/08 の「const 関数から非 const の `Account&` を返していた」と同じ話で、map が持っているのはポインタなので const が浅い。だから `operator[] const` では戻り値を自分で `const Account&` と書いて深さを補っている
  - `deleteAccount` が iterator を必要とする本当の理由は「`delete` するから」ではなく「**`erase` するから**」

### なぜヘルパーが2本必要か
- 疑問: 中身が同じ4行を2回書くのは重複では
- 理解: `clientAccounts.find(id)` の戻り値は `clientAccounts` が const かどうかで変わる
  - 非 const メンバ関数の中では `find` は iterator を返す
  - const メンバ関数（`operator[] const`、そこから呼ばれる `operator<<`）の中では `this` が `const Bank*` なので `clientAccounts` も const。`find` は const_iterator を返す
  - const メンバ関数からは非 const のヘルパーを呼べない（`this` が const なので渡せない）
  - つまり「`operator[] const` から呼びたい」と「`erase` に渡したい」という2つの要求を同時に抱えているので、2本以外に手がない。`std::vector::begin()` に const 版と非 const 版があるのも同じ制約から同じ形に落ちているだけで、権威への追従ではない
  - 同名で末尾の const だけ違うオーバーロード。呼び出し側で選ぶ必要はなく、呼んだ関数が const かどうかでコンパイラが選ぶ
- 選び方のルール
  1. 呼び出し元が const メンバ関数なら const_iterator しか選べない
  2. 非 const メンバ関数なら iterator。erase や second の差し替えが要るなら必須
  3. 4行の重複は C++98 では受け入れる。const 版から `const_cast` で非 const 版を呼ぶ技もあるが、この規模では説明コストの方が高い
- 確認方法: 片方をコメントアウトしてコンパイルすると、iterator 版だけなら `operator[] const` で「const な this から非 const 関数を呼べない」系、const_iterator 版だけなら `erase` で「no matching function」が出る

### コピーで壊せる（新しく気づいた穴）
- `Bank` は `Account*` を生で持ち、デストラクタで `delete` する。コピーコンストラクタと `operator=` はコンパイラが暗黙生成するので `Bank b2 = bank;` で2つの Bank が同じ Account を指し、デストラクタで二重 `delete`
- C++98 の定石: コピーコンストラクタと `operator=` を private に**宣言だけして定義しない**。コピーしようとした時点でコンパイルエラーになる
- main の `Bank bank = Bank();` も形式上はコピー。コピーを禁止するなら `Bank bank;` に直す
