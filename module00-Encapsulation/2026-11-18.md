## 学んだこと（疑問→理解のラリー）
起きた順に並べてある。各項目は「何が引っかかったか → 何が分かったか」。

### 1. `Vector2` と `Graph` の関係が分からなかった
- 最初の考え: `vector<pair<float, float> >` が `Vector2` で、その 1 要素が点
- 引っかかり: そうだとすると `Graph` の役割がない（`Vector2` だけで出力例が作れる）。サイズを `Vector2` に入れる意味もない（`pair` で十分）。辻褄が合わないので「解釈が間違っているはず」と考えた
- 理解: `Vector2` は点のリストではなく点 1 個。`pair<float, float>` 1 個に相当する
  - リストを持つのは `Graph`。`Graph` = サイズ + 点のリスト + 追加と表示の方法
  - `vector<Vector2>` だけでは「どこまで描くか」が決まらない。だから `Graph` にサイズが要る
  - `pair` との違いは名前だけ（`p.first` ではなく `p.x`）
- 混乱の原因: 名前の `Vector` を `std::vector`（可変長配列）と読んだ。数学のベクトルの意味だった

### 2. 数学のベクトルとは何だったか
- 疑問: 2 つの数の組で何を表す概念か
- 理解: 「向き」と「大きさ」を持つ量。平面なら「x 方向にいくつ、y 方向にいくつ」
  - `(3, 2)` は、移動なら「右に 3、上に 2」、位置なら「原点から右に 3、上に 2 の場所」、大きさなら「幅 3、高さ 2」
  - 位置もサイズも同じ形なので、同じ `Vector2` 型で表せる
- この課題では足し算や長さは使わない。「x と y をまとめて持ち運ぶ入れ物」で足りる

### 3. 「ASCII アートで出す」とは何か
- 疑問: 点の位置に `X`、それ以外に `.` を置けばよいのか
- 理解: そのとおり。出力例から読み取れる決まりは 4 つ
  1. y は上が大きい（画面は上の行から出すので、y が最大の行から出す）
  2. 左端に y の目盛り
  3. 最下行に x の目盛り
  4. 文字の間は空白 1 個
- 行頭の `>& ` は PDF の飾りと解釈した（PDF に明記なし）

### 4. なぜ `float` なのか
- 疑問: マスに置くだけなら `int` で足りる。何か意味があるはず
- 次の疑問: ゲームや描画ライブラリの `Vector2` が `float` なのはなぜか。`int` のピクセル座標と RGB で済むのでは
- 理解: 最終的な画面出力は整数のピクセル。`float` を使うのはその手前、位置を計算する段階
  - ゆっくりした移動: 1 回の移動量が 0.33 のとき、`int` だと 0 に切り捨てられ、何回足しても動かない
  - 回転: `(1, 0)` を 45 度回すと `(0.707, 0.707)`。`int` に丸めると `(1, 1)` で、原点からの距離が 1 から 1.41 に伸びる
  - 画面の大きさに依存しない: 世界の座標で持てば、どの解像度にも描ける
- 流れ: 世界の位置（`float`）→ 計算 → ピクセル（`int`）に変換 → 画面。丸めるのは最後の 1 回だけ
- この課題への対応: 点 = 世界の位置、ASCII のマス = ピクセル、`Graph` の表示 = 最後の変換
- `float` の理由は PDF に書かれていない。以上は解釈

### 5. PNG は内部で `float` を持っていると思った
- 最初の考え: PNG も拡大縮小できるので、内部は `float` のはず
- 理解: 逆。PNG（ラスター形式）の中身は整数のピクセルの格子
  - 拡大できるのは、表示するソフトが間の色を計算して作っているから。元の情報は増えないのでぼやける
  - 座標を数値のまま持つのは SVG などのベクター形式
- `float` を持っているのは、PNG を作る側のプログラム（この課題では `Graph`）
- ボーナスで効く場面: `(1.5, 2.3)` は、ASCII では `(2, 2)` のマスに丸まるが、1 単位 = 50 ピクセルの PNG ならピクセル `(75, 115)` に描ける。保存の段階で丸めていないから、粗い出力も細かい出力も作れる

### 6. 四捨五入を選んだ理由が違っていた
- 最初の理由: 四捨五入のほうが、サイズが大きいときに直線が滑らかになりそう
- 理解: 滑らかさは同じ。切り捨ては「四捨五入を 0.5 マスずらしたもの」で、階段の形は変わらない
- 本当の理由
  1. ずれが最大 0.5 マス（切り捨ては最大 1 マス近く）
  2. 切り捨てはすべての点が左下に寄る
  3. 計算結果が 3.0 のつもりで `2.9999998` になっても、マス 3 になる（切り捨てだとマス 2）
- C++98 に `std::round` はない（C++11 から）。`std::floor(x + 0.5f)` を使う

### 7. 「表示の側では範囲を調べ直す必要がない」が何を言っているのか分からなかった
- 引っかかり: 最初に調べたら、もう調べ直す必要がないのは当たり前に思えた
- 理解: 当たり前ではない理由が 1 つある。判定する値と、表示で使う値が別物
  - 追加のときに判定する値: 丸める前の `x`（例: `4.7`）
  - 表示のときに使う値: 丸めた後のマス番号（例: `5`）
  - 丸めると値が変わるので、「丸める前は範囲内、丸めたら外」が起きないかの確認が要る
- 壊れる例: マスが 0〜4 の 5 個で、判定が `0 <= x <= 5` のとき。`4.7` が通り、丸めてマス 5（存在しない）に書き込む
- もう 1 つの条件: 「最初に調べたから安全」は、点の入口が追加の関数 1 つだけのときに成り立つ。リストが public だったり、書き換え可能な参照を返す getter があると、判定を通らない点が入る

### 8. 「点を入れる」のインターフェースが想像できなかった
- 疑問: サイズと点を入力するプログラムなのか。表示した後も入力可能な状態にするのか
- 理解: キーボード入力のプログラムではない。`Graph` はクラスで、`main.cpp` からメソッドを呼ぶ。PDF の「User」はクラスを使うコードを書く人
  - 表示の後も `g` は残っているので、`addPoint` → `print` をもう一度呼べば点が増えたグラフが出る。特別な仕組みは要らない
  - 入力ファイルから点を読むのはボーナス

### 9. サイズ 5 はマス何個か
- 考え: 5 と指定して 6 個になるのは違和感がある。0〜4 の 5 個にする
- そこから決まったこと
  - 出力例（目盛り 0〜5）を再現するにはサイズを `(6, 6)` にする
  - 範囲の判定は `0 <= x <= size.x - 1`。`0 <= x <= size.x` のままだと、7 の「壊れる例」がそのまま起きる

### 10. 簡単すぎる。何かを見落としている気がした
- そのときの考え: 「`addPoint` と `print` は使わせるので public。それ以外から追加できるとコードが煩雑になるので private」。これだけがカプセル化のはずがない
- 理解: 分け方は合っていた。足りなかったのは「なぜ private にするか」の判断基準
  - `Graph` には約束がある: 「中にある点はすべてサイズの範囲内」
  - この約束（不変条件）を守れるのは、入口が `addPoint` だけのとき
  - カプセル化は「全部 private にすること」ではなく、不変条件を守るために入口を絞ること
- 「煩雑になるから」より「約束が壊れ、表示が存在しないマスに書き込むから」のほうが強い理由
- ex00 は「壊れたコードを直す」、ex01 は「同じ考え方を白紙から使う」。コードは少なく、評価の中心は決定を説明できるか（PDF 9 ページ）

### 11. 不変条件とドメインロジックの関係
- 最初の考え: 不変条件 = ドメインロジック
- 理解: 不変条件はドメインロジックの一部
  - ドメインロジック: 業務の決まりごと全体（「入金の 5% を銀行が受け取る」などの計算や手順も含む）
  - 不変条件: その中で「どの時点でも必ず成り立つ条件」（「ID は重複しない」「点はすべてサイズの範囲内」）
- バグの温床になる形: 検査が各所に散らばり、1 か所でも書き忘れると不正なデータが入る。入口が複数あって、全部で検査しているかを誰も保証できない
- 良い形: データを持つオブジェクト自身が入口で検査する。不正な状態のオブジェクトが作れない

### 12. `Vector2` の x と y を private にする検討で、前提を 4 つ間違えた
- そのときの結論: `Vector2` は `Graph` の中に private で定義し、x と y も private、コンストラクタだけ public
- 間違い 1: `std::pair` の中身は private だと思っていた → `first` と `second` は public。そもそも `Vector2` は `pair` を使わず自分で定義する
- 間違い 2: `Vector2` は `Graph` の内部でしか使わない概念だと思った → 必須要件が「add a new **Vector2** onto the Graph」。利用者が `Vector2` を作って渡すので、`main.cpp` から見える必要がある
- 間違い 3: コンストラクタで作れるので getter は要らないと思った → 作る側しか見ていなかった。`Graph` は範囲の判定と表示で x と y を読む
- 間違い 4: 既存の点を変更させないために x と y を private にすると考えた → それは `Graph` のリストが private であることで達成済み。`addPoint` はコピーを保存するので、外の `p.x = 100;` は `Graph` の中の点に届かない
- 見落としが見つかったきっかけ: 呼び出す側のコード（`g.addPoint(Vector2(2, 4));`）と、使う側の処理（判定・表示）を具体的に並べたこと

### 13. 数年運用したら、`Graph` の中で好きに書き換えるメソッドが増えるのでは
- 考え: x と y を private + getter だけにすれば「読むだけ」が守られやすい。ただ、結局 setter を足す人が出るので意味がないかもしれない
- 理解
  - private が防ぐのはクラスの外からの操作だけ。`Graph` 自身のメソッドは止められない
  - setter がなくても `points[i] = Vector2(100, 2);` と丸ごと置き換えられる
- クラスの内側に効くもの
  1. `const`: `const Vector2 size;` はどのメソッドからも変えられない。`void print() const;` は中でメンバーを変えるとコンパイルエラー
  2. クラスを小さく保つ: 約束を壊せるコードが 1 クラスに限られる
  3. テスト
- 「結局 setter を足す人がいる」への答え: カプセル化は「不可能にする」ではなく、うっかりの書き換えを、意図的で目に見える変更に変える。setter を足す・`const` を外すという差分がレビューで見える

### 14. `operator=` を禁止すれば、丸ごとの置き換えも止められるのでは
- 考え: ex00 の `Account` と同じく、`operator=` を private にすればよい
- 理解: `Graph` では使える。`Vector2` では使えない
  - C++98 のコンテナは、要素が代入できることを要求する。`Vector2` の `operator=` を private にするか `const float x;` にすると、`push_back` がコンパイルエラー
- 結論: `Vector2` でできるのは部分的な書き換えの禁止まで。中途半端な縛りになるので、public にして一貫させた

### 15. `std::vector` をやめてポインタで持てばどうか
- 疑問: ポインタの配列なら、`operator=` を禁止しても格納できるか
- 理解: 格納できる。ポインタのコピーはアドレスのコピーで、`Vector2` の `operator=` を呼ばない
- 失うもの
  1. `delete` の責任（デストラクタ）
  2. `Graph` のコピーで同じ点を 2 回 `delete` する問題
  3. `new` の失敗（`std::bad_alloc`）の処理
  4. `delete points[i]; points[i] = new Vector2(100, 2);` と結局置き換えられる
- 結論: もとの目的（`Graph` のメソッドに点を変えさせない）は達成できない。管理コードが増えるだけなので採用しない
- `Vector2 arr[10];`（`Vector2` そのものの配列）は別の話。先に空の要素を作って代入で埋めるので、`operator=` が要る

### 16. 目的が達成できない案を探し続けてしまった
- 気づいたこと: 「`Graph` の中で点を変更させない」は要件ではなく、根拠のないこだわりだった
- 学んだ基準: 手段を探し始める前に「これがないと何が壊れるか」を 1 文で書く
  - 「点のリストが public だと、範囲外の点が入り、表示が存在しないマスに書き込む」→ 書ける。守る価値がある
  - 「`Graph` のメソッドが点を変更できると、…」→ 続きが書けない。ここで打ち切る
- 検討が残したもの: 採用しなかった案の理由が、評価での説明の材料になる（「なぜ private にしなかったか」「なぜポインタで持たなかったか」）

### 17. ヘッダーを書いて分かったこと
- `Vector2(2, 4)` がエラーになった（`no matching function for call to 'Vector2::Vector2(int, int)'`）
  - 最初の考え: コンストラクタは書かなければ自動で public に作られる。`struct` と `class` の違いはデフォルトが public か private かだけ
  - 理解: 2 つとも正しい。ただし自動で作られるのは「引数なし」と「コピー」だけ。引数 2 つのものは自分で書く
  - C++98 では `Vector2 p = {2, 4};` は書けるが、引数の位置に `{2, 4}` は書けない（C++11 から）
  - コンストラクタを書くと、引数なしのコンストラクタと波かっこの初期化は使えなくなる。`push_back` には影響しない
- `struct Vector2 { ... } typedef Vector2;` の `typedef` は C の書き方。C++ では不要
- private の `Graph();` は不要。コンストラクタを 1 つでも宣言すると、引数なしのものは自動では作られない
- `operator=` の戻り値は慣習で `Graph&`
- コピーコンストラクタを private にすると、`Graph g = Graph(...);` は書けない。`Graph g(Vector2(6, 6));` と書く
- 引数名とメンバー名が同じとき、初期化リストの `x(x)` は「外がメンバー、中が引数」で正しく動く。本体の `x = x;` は引数を引数自身に代入するだけ

## 決めたこととその根拠

### 判断基準: 「これがないと何が壊れるか」
- カプセル化は「全部 private にすること」ではなく、不変条件を守るために入口を絞ること
- 手段を探す前に「これがないと何が壊れるか」を 1 文で書く。続きが書けなければ打ち切る

### `Graph` の不変条件は「中にある点はすべてサイズの範囲内」
- 点のリストは private。入口は `addPoint` だけ
- 範囲外の点は `addPoint` でエラーにして断る（表示のときではなく、追加のとき）
- リストが public だと、範囲外の点が入り、表示が存在しないマスに書き込む

### `Vector2` は `Graph` の外に定義し、x と y は public
- 外に置く理由: 必須要件が「User must be allowed to add a new Vector2 onto the Graph」。利用者が `Vector2` を作って渡す
- public にする理由
  1. `Vector2` には不変条件がない（どんな `float` も正しい値）
  2. 丸ごとの代入は `std::vector` に入れる都合で禁止できない。部分的な書き換えだけ禁止しても中途半端になる
  3. `Graph` の中の点は、リストが private でコピーを保存しているので、`Vector2` が public でも外から変えられない
- 採用しなかった案
  - x と y を private + getter: 守れるものが増えない
  - ポインタで持つ（`std::vector<Vector2*>`）: `delete`・コピー・`new` の失敗の管理が増える。`points[i]` の置き換えは結局できる

### サイズは `const`、`print` は `const` メソッド
- サイズを後から縮めると、入っている点が範囲外になり、不変条件が壊れる
- `const Vector2 size;` にすると、`Graph` のどのメソッドからも変えられない
- `Graph` のコピーコンストラクタと `operator=` は private に宣言して禁止

### 保存は `float` のまま、表示のときだけ四捨五入
- 丸めは表示の都合なので、`Graph` の内側に閉じ込める。データは正確なまま残る
- `std::floor(x + 0.5f)` を使う

### サイズ 5 はマス 0〜4 の 5 個
- 「サイズ 5 はマスが 5 個」と説明できる
- 範囲の判定は `0 <= x <= size.x - 1`（丸める前の値で判定）。これを満たせば、丸めた後も 0〜4 に収まる
- 出力例（目盛り 0〜5）を再現するにはサイズを `(6, 6)` にする

### 使い方は `main.cpp` からメソッドを呼ぶ
- キーボード入力のプログラムではない
- 入力ファイルから点を読むのはボーナス
