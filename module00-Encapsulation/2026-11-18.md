## 理解を直したこと

### `Vector2` は点のリストではなく、点 1 個
- 最初の理解: `vector<pair<float, float> >` が `Vector2`
- 正しい理解: `pair<float, float>` 1 個に相当するものが `Vector2`。リストは `Graph` が持つ
- 名前の `Vector` は `std::vector` ではなく、数学のベクトル（2 つの数の組）
- サイズ（幅と高さ）も「数 2 個の組」なので、同じ `Vector2` 型を使う

### `float` である理由（PDF に記載なし。解釈）
- 位置を計算する段階では小数が要る
  - ゆっくりした移動: 1 回の移動量が 0.33 のとき、`int` だと 0 に切り捨てられて動かない
  - 回転: `(1, 0)` を 45 度回すと `(0.707, 0.707)`。`int` に丸めると形が歪む
  - 画面の大きさに依存しない: 世界の座標で持てば、どの解像度にも描ける
- 流れ: 世界の位置（`float`）→ 計算 → ピクセル（`int`）に変換 → 画面 / PNG
- PNG の中身は整数のピクセルの格子。`float` を持っているのは PNG を作る側のプログラム

### 自動で作られるコンストラクタは「引数なし」と「コピー」だけ
- `Vector2(2, 4)` と書くには、引数 2 つのコンストラクタを自分で書く
- C++98 では `Vector2 p = {2, 4};` は書けるが、引数の位置に `{2, 4}` は書けない
- `std::pair` の `first` / `second` は public

## 決めたこととその根拠

### 判断基準: 「これがないと何が壊れるか」
- カプセル化は「全部 private にすること」ではなく、不変条件を守るために入口を絞ること
- 不変条件: どの時点でも必ず成り立っていなければならない条件。ドメインロジックの一部
- 手段を探す前に「これがないと何が壊れるか」を 1 文で書く。続きが書けなければ打ち切る

### `Graph` の不変条件は「中にある点はすべてサイズの範囲内」
- 点のリストは private。入口は `addPoint` だけ
- 範囲外の点は `addPoint` でエラーにして断る（表示のときではなく、追加のとき）
- リストが public だと、範囲外の点が入り、表示が存在しないマスに書き込む

### `Vector2` は `Graph` の外に定義し、x と y は public
- 外に置く理由: 必須要件が「User must be allowed to add a new Vector2 onto the Graph」。利用者が `Vector2` を作って渡す
- public にする理由
  1. `Vector2` には不変条件がない（どんな `float` も正しい値）
  2. 丸ごとの代入は `std::vector` に入れる都合で禁止できない（C++98 のコンテナは要素が代入できることを要求する）。部分的な書き換えだけ禁止しても中途半端になる
  3. `Graph` の中の点は、リストが private でコピーを保存しているので、`Vector2` が public でも外から変えられない
- 採用しなかった案
  - x と y を private + getter: 守れるものが増えない
  - ポインタで持つ（`std::vector<Vector2*>`）: `Vector2` を変更不可にできるが、`delete`・コピー・`new` の失敗の管理が増える。`points[i]` の置き換えは結局できる

### サイズは `const`、`print` は `const` メソッド
- サイズを後から縮めると、入っている点が範囲外になり、不変条件が壊れる
- `const Vector2 size;` にすると、`Graph` のどのメソッドからも変えられない（private はクラスの外にしか効かない）
- `Graph` のコピーコンストラクタと `operator=` は private に宣言して禁止

### 保存は `float` のまま、表示のときだけ四捨五入
- 丸めは表示の都合なので、`Graph` の内側に閉じ込める。データは正確なまま残る
- 四捨五入を選んだ理由
  1. ずれが最大 0.5 マス（切り捨ては最大 1 マス近く）
  2. 切り捨てはすべての点が左下に寄る
  3. 計算結果が `2.9999998` になっても、マス 3 になる
- C++98 に `std::round` はない。`std::floor(x + 0.5f)` を使う

### サイズ 5 はマス 0〜4 の 5 個
- 「サイズ 5 はマスが 5 個」と説明できる
- 範囲の判定は `0 <= x <= size.x - 1`（丸める前の値で判定）。これを満たせば、丸めた後も 0〜4 に収まる
- 出力例（目盛り 0〜5）を再現するにはサイズを `(6, 6)` にする

### 使い方は `main.cpp` からメソッドを呼ぶ
- キーボード入力のプログラムではない。PDF の「User」はクラスを使うコードを書く人
- 入力ファイルから点を読むのはボーナス
