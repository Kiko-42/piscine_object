# Module 00 - Encapsulation / S2: 外から壊せる箇所を見つけた（2026-11-04）

## 見つけたこと
- 添付プログラムは Account も Bank も `struct` で、`private:` が1つも無い。全フィールドが public
- だから `main` から `accountA.value = 100`、`bank.liquidity -= 200` のように、Bank を通さず直接書き換えられる
- 守るべき状態（不変条件）の候補:
  - Account の残高は Bank の操作（入金・出金・貸付）経由でしか変わらない
  - Account の id は作った後に変わらない
  - Bank の liquidity と手数料は Bank 自身しか触れない

## 疑問→理解のラリー

### struct と class
- 疑問: struct には private が無いから、class に書き換えるしか手段がないと思っていた
- 理解: C++ では struct と class は同じ物。違いは「何も書かない時の既定」だけ（struct=public、class=private）。struct のまま `private:` と書けば隠せる。C++98 から同じ

### friend
- 疑問: friend が何かわからないまま前に進んだ記憶がある
- 理解: 「この関数（またはこのクラス）だけは私の private を触ってよい」という例外許可
  - **許可を出すのは触られる側**。Bank が Account の中身を変えたいなら、Account の中に `friend class Bank;` と書く
  - Bank 自身のメンバ関数（registerAccount 等）が Bank の private を触るのに friend は要らない。メンバは最初から触れる
  - 使うが少なめ。典型は `operator<<` と「片方だけが相手を変えてよい密な2者（Bank/Account）」。増やすと誰が状態を変えられるか追えなくなる。まず public メソッドで足りるか考える
  - 今は全部 public なので friend は意味を成していない。private にした時に初めて効く

### std::ostream&
- 疑問: 戻り値は ostream の「値」？アドレス？
- 理解: どちらでもなく**参照**だった。値と参照が混同していた。cout そのものに付けた別名。コピーしない（ostream はコピー禁止）、ポインタでもない
- なぜ参照で返すか: `cout << a << b` は `(cout << a) << b` と評価される。左の `<<` が cout 自身を返すから `<< b` を繋げられる

### operator<< はどこの関数か
- 疑問: Bank の中に書いてあるからメンバ関数なのでは？メンバなら private を読めるはずで friend の意味は？
- 理解: **friend を付けた関数は、波括弧の中に本体を書いてもメンバではない**。外の関数に private を読む許可を出しているだけ
  - 見分け方: `Bank::` が付かない、`this` が無い、Bank を引数で受け取って `p_bank.liquidity` と書く
  - 実験: `friend` を消すと本体が中にあってもコンパイルエラーになる（メンバなら通るはず）
  - クラスの中には宣言だけ置き、定義を外（.cpp）に書いても同じ動作。それが標準形
  - メンバにしない理由: メンバの `operator<<` は左辺が Bank になり `cout << bank` と書けない
  - `cout << 42` の `<<` は ostream のメンバ。`cout << bank` 用の `<<` は自分がクラスの外に新しく書く関数で、それを「オーバーロード」と呼ぶ
