## やったこと（12:14〜13:19・コードは未コンパイル）
- Bank を `struct` → `class` に。`liquidity`・`new_id`・`clientAccounts` を private 側へ
- Account を Bank の内部クラス（private）に移した（subject: "The Account structure must be internal to the Bank structure"）
- `std::vector<Account*>` → `std::map<size_t, Account*>` に替え始めた。ID は Bank が持つカウンタ `new_id` で発番（vector.size() は削除後に重複するので不可）
- `deleteAccount` と `operator[]` を書き始めたところで、operator[] の分からない点を残したまま他の関数へ手を広げてこんがらがったので止めた

## 決定と理由
- **ID はカウンタ**: 「同じ ID が2つ存在してはならない」を削除後も守るため。vector.size() は erase で減る
- **modify ＝ deposit / withdraw / loan**: subject の "modify the accounts" に setValue は作らない。5% 手数料と残高チェックを必ず通す経路だけを残す。id は不変
- **Account の getter は const**: Account を `const Account&` で受け取る側に「読むだけ」を型で約束するため。const 関数の中では this が const になり、メンバ代入はコンパイルエラーになる

## 疑問（未解決・次に開く箇所）
1. **operator[] をどう書くか**。今の形 `friend Account& operator[](size_t id) const` はエラー2つ:
   - operator[] は **メンバ関数でなければならない**（friend＝非メンバにはできない）
   - 非メンバに `const` 修飾は付けられない。メンバにして `const Account& operator[](size_t id) const` が正しい形
   - 中身は `clientAccounts.find(id)` が返すのは **イテレータ**。`->second` で Account* を取り出し、`*` で参照に。見つからない時（`end()`）の扱いを決める
2. `map` に `push_back` は無い → `clientAccounts[new_id] = new Account(new_id, value)` か `insert`
3. `deleteAccount` は `delete` の後に map からも `erase` する（ポインタだけ消すと map に dangling が残る）
4. `operator<<` の中の `for (i < size())` は map では使えない。イテレータで回す（subject が禁じる while/for は「ID で口座を探す」ループ。全件表示のループは別）
5. 内部クラスの前方宣言 `class Account;` を Bank の先頭に置くか、hpp に分けて読みやすくするか（設計の好み。後で）
