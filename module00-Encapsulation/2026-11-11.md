# Module 00 - Encapsulation / S8: deposit で 5% を銀行へ・入力の検証と例外クラス・createAccount から初期残高を外した（2026-11-11）

## やったこと
- `static const int DEPOSIT_FEE_PERCENT = 5;` を `Bank` の private に置いた
- `deposit` で手数料を計算し、`liquidity` に足すようにした。口座には `value - 手数料` が入る
- `deposit` と `withdraw` に検証を入れた（0 以下の金額、存在しない口座、手数料が取れない入金、残高不足）
- 例外クラス `DepositTooSmall` と `InsufficientFunds` を `Bank` の public に作った（`std::runtime_error` を継承）
- `createAccount` から初期残高の引数を外し、作った口座の id を返すようにした。`Account` のコンストラクタは `id` だけを受け取り、`value(0)` で始まる
- `Account::id` を `const size_t` にした
- クラス定義の並びを public → private の順に入れ替えた
- **未完了**: `main` が古い `createAccount(100)` のままで、ファイル全体はコンパイルが通らない
- 確認済み（`main` だけ差し替えたコピーを `c++ -std=c++98 -Wall -Wextra -Werror` でコンパイルして実行）
  - `deposit(a, 100)` と `deposit(a, 400)` のあと、残高 475、Liquidity 225
  - `deposit(a, 19)` は `DepositTooSmall`、`deposit(a, 0)` と `deposit(a, -5)` は `invalid_argument`
  - `deposit(42, 100)` は `out_of_range` で、Liquidity は変わらない
  - 残高 0 の口座からの `withdraw` と、残高を 1 超える `withdraw` は `InsufficientFunds`。全額の引き出しは通る
  - `Bank::DepositTooSmall` と `Bank::InsufficientFunds` は外から型を指定して catch できる

## 要件について決めたこと
- 手数料は入金額の 5%。値は整数のパーセント（`5`）で持ち、計算は `value * DEPOSIT_FEE_PERCENT / 100`
- 端数は切り捨て（客の得になる側）
- 手数料が 0 になる入金（5% なら 20 未満）は受け付けない。判定は金額の下限ではなく「計算した手数料が 0 以下か」で行う。率を変えても判定がずれないため
- 0 以下の金額は、入金も引き出しも受け付けない
- 残高を超える引き出しは受け付けない。全額の引き出しは許す
- 例外の使い分け
  - 引数として意味をなさない値（0 以下の金額）→ `std::invalid_argument`
  - 存在しない口座 → `std::out_of_range`
  - 値はまともだが銀行のルールに反する → 専用の例外クラス（`DepositTooSmall`、`InsufficientFunds`）
- 検証をすべて済ませてから状態を変える。例外が出たときに `liquidity` や残高が中途半端に変わらない
- 口座は残高 0 で開設する。残高を変えられるのは `deposit` と `withdraw` だけ。開設時の入金だけ 5% を免れる抜け道をなくすため
- `createAccount` は作った口座の id を返す。呼び出し側が id を推測しなくて済む
- `Account` は自分の id を持ち続ける（`const`）。`const Account&` を単体で受け取った側が、どの口座か分かるようにするため

## 疑問→理解のラリー

### 5% の定数名は何がいいか
- 理解: 名前に入れるのは「何の数字か」と「単位」の2つ
  - `BANK_RATE` は金利と紛らわしい。`FIVE_PERCENT` は値を変えた瞬間に名前が嘘になる
  - 値を `0.05` で持つなら `RATE`、`5` で持つなら `PERCENT`。**名前と値の持ち方はセットで決まる**
- 最初は `DEPOSIT_FEE_RATE` のほうが解釈の隙間が小さいと思った。`0.05` で持つならそのとおりだが、`5` で持つなら `RATE` では単位が決まらない
- 結論: `Bank` のドメイン知識なので `Bank` の中に置きたい。クラス内で初期化できる `static const int` と `PERCENT` の組にした

### なぜ `static const` なのか。`const int` ではだめか
- 理解: だめではない。違いは「誰の持ち物か」
  - `const int`（非 static）: オブジェクト1つごとに値を持つ。「銀行ごとに手数料が違ってよい」という表現になる
  - `static const int`: クラスに1つ。「Bank というものの共通ルール」という表現になる
- C++98 では、非 static メンバをクラス内で `= 5` と初期化する書き方自体ができない（初期化リストに書く）

### なぜ `static const double` はクラス内で初期化できないのか
- 理解: クラス内の `static` メンバは本来「宣言」だけで、定義はクラス外に書くのが原則。`static const int` のクラス内初期化はその例外
  - 整数はコンパイル時に値が完全に確定するので、実体を作らずに値を埋め込める
  - 浮動小数は、コンパイルするマシンと実行するマシンで精度や丸めが異なる可能性があるので、当時の規格はコンパイル時定数として扱わなかった
- C++11 以降は `static constexpr double` と書ける。`const double` のままなら、クラス外で `const double Bank::RATE = 0.05;` と定義する
- 補足: `static const int` でも、const 参照で受ける関数（`std::min` など）に渡すと実体が必要になり、リンクエラーになる（C++17 より前）。そのときはクラス外に `const int Bank::DEPOSIT_FEE_PERCENT;` を足す

### 手数料が常に 0 になった
- 書いたコード: `value * (DEPOSIT_FEE_PERCENT / 100)`
- 理解: 括弧の中が整数同士の割り算で `5 / 100 = 0`。**掛けてから割る**（`value * DEPOSIT_FEE_PERCENT / 100`）
- コメントの `//rounded` も誤りだった。整数の割り算は四捨五入ではなく切り捨て

### double を使えば少額でも手数料を取れるのでは
- 疑問: このままだと 100 円未満の入金で手数料が発生しない
- 訂正: 括弧を外した式なら、0 になるのは 100 未満ではなく **20 未満**（19 × 5 / 100 = 0、20 × 5 / 100 = 1）
- 理解: 問題は計算の型ではなく、**お金の最小単位が 1 円（`int`）であること**。10 円の 5% は 0.5 円で、どちらかへ丸めるしかない
  - 全部を double にすると 0.5 円は持てるが、誤差が残高に溜まるのでお金には向かない
  - 決めるべきは丸めの方針。切り上げなら `(value * DEPOSIT_FEE_PERCENT + 99) / 100`
  - 端数を正確に持ちたいなら、double ではなく単位を細かくする（セントや銭を `int` で持つ）
- 結論: 切り捨てのままにして、手数料が 0 になる入金は受け付けないことにした

### どの例外を投げるか
- 理解: `std::invalid_argument` は「引数の値そのものが条件を満たしていない」
  - `std::out_of_range` は「添字やキーが範囲外」。すでに「口座がない」で使っているので、分けておくと catch で原因を区別できる
  - `std::domain_error` は数学関数の定義域外向け
- 負の金額と「小さすぎる入金」は性質が違う。前者は引数として無意味、後者は銀行のルール違反。標準例外にちょうど合うものがないので、例外クラスを自作した
- 例外クラスを private に置くと、外から `catch (Bank::DepositTooSmall&)` と書けない。型を分けた意味がなくなるので public に置く
- メッセージに下限の金額を出すなら定数から組み立てる（直書きすると、率を変えたときに文言だけ古くなる）。今回は手数料で判定する形にしたので、金額は出していない

### 検証と変更の順番
- 最初のコードは、`getAccount` より先に `liquidity += fee` を書いていた。存在しない id を渡すと、例外の前に `liquidity` だけ増える
- 理解: 先に全部検証し、最後に状態を変える

### 残高チェックを入れる関数を間違えた
- `InsufficientFunds` のチェックを `withdraw` ではなく `deposit` に入れてしまい、`main` の `deposit(0, 400)` が異常終了した
- 学び: コンパイルが通っても、実行して出力を見るまで確認にならない

### insufficient funds の意味
- 「残高不足」。insufficient は「足りない」（sufficient の否定）、funds は「資金」（この意味では複数形）。銀行やATMの決まり文句

### `Account` の id は要らないのでは
- 疑問: map のキーで管理しているので、`Account` が id を持つ必要がない気がした
- 理解: 分かれ目は「`Account` が `Bank` の外に単体で出ていくか」
  - 消すと、`const Account&` を受け取った側がどの口座か分からない。`Account` の `operator<<` も `[id] - [value]` を自分で出せなくなる
  - 重複が害になるのは値がずれうるとき。`id` は一度決まったら変える経路がないので、ずれない。`const` にすればコンパイラが保証する
  - `Account` を外に出さないと決めるなら消せるが、残るのが `int value` だけになり、`std::map<size_t, int>` で足りてしまう
- 補足: `const` メンバを持つクラスは代入ができなくなる。`Account` はポインタで map に入れているので影響はない
