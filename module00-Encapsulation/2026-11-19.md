## 決めたこととその根拠

### 引数は `const Vector2&` で渡す
- 値渡しだと、`addPoint` でコピーが 2 回起きる（引数に 1 回、`push_back` で 1 回）。参照なら 1 回
- `Vector2` は 8 バイトなので、速度の差は実質ない
- それでも参照にする理由: 「クラス型の引数は `const` 参照で渡す」という慣習に合わせる。型が大きくなっても書き直さなくて済む
- `const` 参照なら、`g.addPoint(Vector2(2, 4));` のような一時的な値もそのまま渡せる（`const` のない参照には渡せない）

### 例外の型
- 範囲外の点: `std::out_of_range`
- サイズが不正: `std::invalid_argument`
- どちらも `<stdexcept>`。自分の例外クラスは作らない

### サイズは 0 より大きく `MAX_SIZE` 以下
- 0 ちょうども断る（マスが 0 個になるため）
- 上限を決める理由: 無限大だけ断っても `1e30` が通り、`print` が終わらない。上限 1 つで、巨大な値と無限大をまとめて断れる
- `MAX_SIZE` は 10
  - 10 以下なら目盛りが 1 桁（0〜9）で、出力例と同じ形で揃う
  - 11 以上にすると 2 桁の目盛りが出て、`std::setw` で列を揃える処理が要る
- 置き方: `Graph` の private に `static const int MAX_SIZE = 10;`
  - `static const` の整数は、C++98 でもクラスの中で値を書ける。`float` は書けないので `int`
  - private にする理由: 利用者が知る必要のない実装の都合

### 条件は「正しい条件に当てはまらなければ断る」の形で書く
- NaN との比較はすべて false になる。`if (size.x <= 0)` と書くと NaN が通る
- `if (!(size.x > 0 && size.x <= MAX_SIZE && ...))` と書けば、0・負の数・巨大な数・無限大・NaN をすべて断れる
- 点の側は `if (!(p.x >= 0 && p.x <= size.x - 1 && p.y >= 0 && p.y <= size.y - 1))`
- NaN が通ると、`print` で NaN をマス番号に変換する箇所が未定義動作になる（共通ルール「どんな状況でもクラッシュしないこと」）

### PNG のボーナスは `MAX_SIZE` を大きくする理由にならない
- PNG の画像の大きさは、サイズではなく倍率で決まる（サイズ 10、倍率 50 → 500 × 500 ピクセル）
- PNG では上限がないとメモリが足りなくなる（サイズ 1000、倍率 10 → 10000 × 10000 × 3 バイト = 300 MB）

## 学んだこと（疑問→理解のラリー）

### 参照渡しの目的は、コピーの手間を 1 つ減らすためか
- 理解: そのとおり。ただし `Vector2` では差が出ない。差が出るのは `std::string` や `std::vector` のような大きい型（要素が 100 万個あれば 100 万個のコピー）
- コピーできない型（コピーコンストラクタが private の `Graph`）は、参照でしか渡せない

### NaN は何のためにあるのか。NULL と近い概念か
- 理解: NaN は「計算の答えが数として存在しない」ことを表す値。`0.0f / 0.0f`、`sqrt(-1.0f)`、無限大 − 無限大 で生まれる
- 存在意義: 計算を止めずに、失敗を最後まで運ぶ
  - 整数の `1 / 0` はその場で止まる。`float` は止まらずに NaN を返す
  - NaN を含む計算の結果はすべて NaN。最後に 1 回調べれば失敗が分かる
  - 代わりに、検査しないと NaN が黙って流れ込む
- NULL との関係: 別の層の概念。NULL はポインタが「どのオブジェクトも指していない」、NaN は浮動小数点数が「数ではない」。共通点は、使う前に検査が要る特別な値であること
- NULL の理解の補足: NULL は「値を入れていない」ではなく、「どこも指していない」という値を明示的に入れた状態。値を入れていないポインタは、でたらめなアドレスを持っている

### `float` のビット列と特別な状態
- 忘れていたこと: 3 つの部分は「符号部・指数部・仮数部」（基数は 2 で固定なので保存されない）
- 並び: 符号部 1 ビット | 指数部 8 ビット | 仮数部 23 ビット
- 特別な状態は指数部で決まる

| 指数部 | 仮数部 | 意味 |
|---|---|---|
| 全部 0 | 全部 0 | 0（+0 と −0） |
| 全部 0 | 0 以外 | とても小さい数（非正規化数） |
| 全部 1 | 全部 0 | 無限大（+∞ と −∞） |
| 全部 1 | 0 以外 | NaN |
| それ以外 | 何でも | 普通の数 |

- 例: `1.0f` は `0x3F800000`、+∞ は `0x7F800000`、代表的な NaN は `0x7FC00000`

### NaN は自分自身と等しくない「可能性がある」と思った
- 最初の考え: NaN のビット列が 1 種類ではないので、判定がややこしくなり、自分自身と等しくないこともある
- 理解: 「可能性」ではなく常に等しくない。ビット列が完全に同じでも `x == x` は false
  - `float` の比較はビット列を比べていない。規格（IEEE 754）が「NaN を含む比較は false」と決めている
  - だから判定は簡単で、`x != x` の 1 つで全種類の NaN を検出できる
- C++98 に `std::isnan` はない（C++11 から）

### 無限大は `size.x == inf` で断ればよいか
- 理解: 書けるが（`<limits>` の `std::numeric_limits<float>::infinity()`）、無限大だけ断っても巨大な値が通る。上限を決めるほうがよい

### C++ で PNG を出すとはどういうことか
- 理解: プログラムが `graph.png` というファイルを作り、PNG の形式どおりのバイト列を書き込む（`std::ofstream` のバイナリモード）
- PNG の構造: 署名（固定 8 バイト）→ IHDR（幅・高さ・色の形式）→ IDAT（ピクセルのデータ。zlib の形式で包む）→ IEND
- 外部ライブラリが禁止なので、自分で書く
  - 圧縮は省ける（zlib の「圧縮せずにそのまま入れる」形式を使う）
  - 省けないのは検査用の値 2 種類（CRC-32 と Adler-32）の計算
  - 全体で 100〜150 行ほど
