## 決めたこととその根拠

### `print` は `paper`（マスの格子）に書き込む方法にする
- 検討した案: 自動で並べ替えるコンテナ（`set`）に点を入れ、イテレータで先頭から見ていく
- 採用しなかった理由
  - 全部のマスに 1 文字ずつ出す処理は省けない。`set` でも二重ループは残り、並べ替えの手間が足されるだけ
  - `Vector2` 用の比較関数が要る。しかも丸めた値で比べないと、同じマスの点が 2 個並ぶ
  - 「行の順番」「丸め」という表示の都合が、データの持ち方に入り込む
- `paper` なら、同じマスに 2 個来ても `true` を 2 回書くだけ。線や PNG も「格子に書き込む」形で延長できる

### マスの個数はサイズを四捨五入した値
- `width = floor(size.x + 0.5f)`、`height = floor(size.y + 0.5f)`
- `addPoint` の範囲（`0 <= x <= size.x - 1`）と一致する
- `paper` の大きさと出力のループの両方で、この `width` と `height` を使う

### `addPoint` は `const Vector2&` を受け取る形のままにする
- 検討した案: `addPoint(float x, float y)` に変える（呼び出し元で毎回 `Vector2` の変数を作るのが使いにくかった）
- 分かったこと: 使いにくさの原因は `const` がなかったこと。`const Vector2&` なら `g.addPoint(Vector2(2, 4));` と書ける
- `Vector2` を受け取る形を残す理由: 必須要件が「add a new **Vector2** onto the Graph」
- `g.addPoint(2, 4);` と書きたくなったら、`addPoint(Vector2(x, y))` を呼ぶだけの 2 つ目の入口を足す。検査は 1 か所のまま

## 学んだこと（疑問→理解のラリー）

### `inf` や NaN を引数でどう渡すのか（S18）
- 理解: `<limits>` の `std::numeric_limits<float>::infinity()` と `quiet_NaN()`。C++98 で使える
- 負の無限大は `-` を付ける
- `INFINITY` / `NAN` のマクロは C99 由来で、C++98 では保証されない
- 確かめたこと: `x > 0 && x <= 10` は、無限大・負の無限大・NaN のすべてで false。`nan <= 0` も false

### テストが、壊れたコンストラクタでも通っていた（S18）
- 最初の書き方: 1 つのテストに `try` を 2 つ並べ、`catch` で `return`
- 起きたこと: コンストラクタを「y だけ検査する」「常に例外を投げる」に壊しても、テストは全部通った
- 原因 1: 最初の `catch` で `return` するので、2 つ目が実行されない。「どれか 1 つが断られれば合格」になっていた
- 原因 2: 成功する場合のテストがなかった。何でも断るコンストラクタが合格する
- 理解: 1 件を確かめる関数（`expectInvalidSize`）を作り、1 件ずつ呼ぶ。成功する場合は、例外が出なければ合格
- この不具合で隠れていたもの: `Vector2(1, -0)`（`-0` は 0。`-1` の書き間違い）

### 並べ替えるコンテナを使えば `print` が速くなるか
- 最初の考え: `paper` を作らずに、`set` のイテレータを先頭から見ていけば 1 行ずつ出せそう
- 理解: 速くならない（上の「決めたこと」）
- 計算量の書き方: 「N」が 2 種類を指していた。マスの数（幅 × 高さ）と、点の数は別の量

### `const` を付けると、なぜ一時的な値を渡せるのか
- 引っかかり: 「`const` の参照には一時的な値を渡せる」を言葉のまま暗記したくなかった
- 理解: 機械の都合ではなく、バグを防ぐための言語の設計
  - `const` のない参照の引数は「呼び出し元の変数を書き換える」という意味
  - 例: `void incr(int& x) { x++; }` に `double d` を渡す。許されると、`d` を `int` に変換した一時的な値が増えるだけで、`d` は変わらない。エラーも警告も出ない
  - 初期の C++ ではこれが許されていて、実際にバグが起きたので禁止になった
  - `const` の参照は「書き換えない」という約束。書き込みがないので「書き込みが消える」事故が起きない。だから許される
- 言い方の整理: `const` は「一時的な値を受け取るための印」ではなく「書き換えない」という約束。その結果として一時的な値も渡せる
- 確かめたこと
  - `incr(d)` のエラー: `cannot bind non-const lvalue reference of type 'int&' to a value of type 'double'`
  - `void show(const int& x)` に `d` を渡すと、`x` のアドレスは `d` と違う。`x` は変換で作られた一時的な値を指している（一時的な値はメモリ上に実在する）
- 一時的な値の寿命: それを作った文の終わり（`;`）まで。`addPoint` の実行中は有効で、`push_back` がコピーを保存するので、消えても困らない
- 設計の判断だと言える根拠: C++11 で、一時的な値に結び付いて書き換えもできる参照（`Vector2&&`）が追加された

### `./graph` が `Assertion '__n < this->size()' failed` で落ちた
- 原因: `std::vector<std::vector<bool> > paper;` が要素 0 個のまま、`paper[y][x]` に書き込んでいた
- 理解: `vector` の `[]` は自動では広がらない。メッセージは「添字 `__n` が要素数 `size()` より小さい」という条件が破れた、という意味
- 直し方: 大きさを指定して作る。`paper(height, std::vector<bool>(width, false))` は「`width` 個の `false` が並んだ行を `height` 個」
