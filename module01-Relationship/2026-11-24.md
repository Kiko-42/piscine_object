# Module 01 - Relationship / S2: 4 つの組の「関係・個数・誰が誰を知っているか」を決めた・道具は main にあり在庫リストは作らない・GetTool の get は getter の get（2026-11-24）

## 決めたこととその根拠
メンバとメソッドは決めていない。後から変えると影響が広いものだけを先に決めた。

| 組 | 関係 | 個数 | 誰が誰を知っているか |
|---|---|---|---|
| `Worker` と `Position` / `Statistic` | composition | 1 つずつ | `Worker` → 両方。逆はなし |
| `Worker` と `Tool` | aggregation | `Worker` 1 人に Tool が 0 個以上。Tool 1 個に持ち主が 0 か 1 人 | 双方向。`Worker` → Tool のリスト、`Tool` → 今の持ち主 |
| `Tool` と `Shovel` / `Hammer` | inheritance | なし | 子 → 親。親は子を知らない |
| `Workshop` と `Worker` | association | 多対多 | 双方向。`Workshop` → Worker のリスト、`Worker` → 登録先のリスト |

### `Worker` と `Position` / `Statistic`
composition。`Worker` インスタンス固有の属性を表すものなので、`Worker` が消えたら一緒に消える。個数は 1 つずつ。
`Worker` が `Position` と `Statistic` を読み取れればよく、逆のアクセスは必要ない。

### `Worker` と `Tool`
aggregation。`Worker` が消えても `Shovel` は消えてはいけないし、そもそも道具なので composition ではない。
`Tool` が `Worker` に機能を contribute する向きがある疎結合なので、association ではなく aggregation。

Workerが持てる個数は種類ごとに 1 つとは制限しない。ボーナスが "the first tool of the right type" と書いていて、同じ種類を複数持つ前提になっている。制限すると、課題文にない規則と種類の検査が増える。

`Worker` は道具を `Tool*` のリストで持ち、`use()` を呼ぶだけ。種類を知る必要があるのはボーナスの `GetTool` だけ。
`Tool` も今の持ち主を知っている必要がある。すでに誰かが持っている道具を別の `Worker` に渡したとき、元の持ち主から外すために、道具から持ち主をたどるから。
道具インスタンスの識別はポインタの比較で足りる。ID は作らない。

### `Tool` と `Shovel` / `Hammer`
親子関係。`Tool` は抽象クラスで、`use` を `Shovel` と `Hammer` それぞれ固有の `use` にする。`Worker` は持っている道具の `use` を呼ぶだけで機能を使い分けられる。
個数の概念は必要なく、定義だけあればいい。`Shovel` は `Hammer` を知らない。独立したオブジェクト。
`Tool` は子クラスのインスタンスを知らない（疑問 2）。

### `Workshop` と `Worker`
association。`Workshop` は `Worker` のリストを持つ。`Worker` は複数の `Workshop` に登録できるし、`Workshop` も複数の `Worker` を持てる。どちらも相手の持ち物ではない。
`Workshop` の `executeWorkDay` は、登録されている全員の `work` を呼ぶだけ。`Worker` が今働いているかを `Workshop` が見る必要はない。
`Worker` も自分の登録先を知っている必要がある。`work` は「登録されていれば働く」なので自分が登録済みかを知る必要があるし、ボーナスの「道具を失ったら自動で外れる」にも使う。

### 双方向にするもう 1 つの理由
`Worker` と `Tool`、`Workshop` と `Worker` のどちらも、片方が先に消えたときに相手のリストから自分を外す必要がある。外さないと、消えたオブジェクトを指すポインタが残って落ちる（落ちたら 0 点）。

## 疑問に思ったことと、その答え

### 疑問 1: aggregation にした場合と association にした場合の設計の差がわからない
最初の理解: `Worker` と `Tool` は、`Tool` が `Worker` に機能を contribute する感じが強いから aggregation。でも association にしなかった理由を求められると難しい。
`Workshop` と `Worker` を考えていて出た仮説: aggregation と呼ばれるのは一方からしか contribute していない状態というだけなのかな。もし互いに contribute しているならそれは疎結合の association と呼ぶし、もし片方からしか contribute していない疎結合なら、それは aggregation と呼ぶみたいな。

答え: 仮説のとおり。
- コードの差はほとんどない。どちらもポインタを持つだけ
- 差が出るのは個数
  - `Worker` と `Tool`: 道具は同時に 1 人にしか属さない。`Worker` が「全体」、道具が「持ち物」
  - `Workshop` と `Worker`: 多対多で、どちらも相手の持ち物ではない

評価で「なぜ association ではないのか」と聞かれたときの 1 文:

> 道具は 1 人の持ち物として扱い、渡すと元の持ち主から外れるから。

（答えを聞いたあとの言語化はなし。仮説がそのまま合っていた）

### 疑問 2: `Tool` は、生成されたすべての子クラスのインスタンスにアクセスできる必要がある？
最初の理解: そうでないとボーナスの `GetTool<ToolType>` は実装できない。`Worker.GetTool<Shovel>` をして、どうやって `Tool` クラスの public メンバにアクセスするかがわからない。抽象クラスだからインスタンス化はできない。`Shovel` クラスが static な在庫 list を保持して、コンストラクタで必ずそのリストに自身を追加するようにすればいいのかな。

答え: 必要ない。static な在庫リストも要らない。
- 抽象クラスは「`Tool` 単体のオブジェクトを作れない」だけ。`Tool*` は作れて、`Tool*` が `Shovel` を指せる
- `GetTool<ToolType>()` は `Worker` のメソッド。探す先は `Worker` が持っている道具のリストだけ
- リストの `Tool*` を 1 つずつ `dynamic_cast<ToolType*>` にかけて、最初に `NULL` でなかったものを返す。型が違えば `NULL` になる

（しっくりこないまま疑問 3 に続く）

### 疑問 3: 道具の在庫リストがどこにあるべきなのかがわかっていない
最初の理解: 道具は worker に関係ないところで生成されて、それを worker にわたしたり、worker が返却すると道具の在庫リストのようなところに戻るものだと思っている。だから "get the first tool of the right type" の get は from 在庫リストなんじゃないの？

答え: 在庫リストはどこにも作らない。課題文に在庫リストは出てこない。
- 道具は `main` の変数として存在する。`Worker` はそれを指すポインタを持つだけ
- 「返却する」は、`Worker` のリストからポインタを消すこと。道具そのものはどこにも移動しない。戻り先は要らない
- 「`Worker` が消えても `Shovel` は消えない」も、これで自然に満たせる。`Worker` は道具を作っても壊してもいないから
- 混乱の元は、「渡す・返す」を物の移動として考えたこと。コードでは物は動かず、「誰がそのポインタを持っているか」が変わるだけ
- 課題文は「どこから get するか」を明記していない。ただ `Worker` クラスのメソッドと指定しているので、「その `Worker` が持っている道具から」と読む。在庫から取る読み方だと、`Worker` のメソッドである理由がなくなる

```cpp
Shovel shovel;             // 道具は main が作る。main が終わるまで生きている
Worker alice;
Worker bob;

alice.giveTool(&shovel);   // alice のリストに &shovel が入る
bob.giveTool(&shovel);     // alice のリストから外れ、bob のリストに入る
bob.takeTool(&shovel);     // bob のリストから外れる。shovel は main にそのまま残る
```

（`giveTool` / `takeTool` は仮の名前）

### 疑問 4: アリスに割り当てられている shovel を get するってのが違和感がある。すでにわたされているものを get するのか？
答え: この get は「手に入れる」ではなく、getter の get。`getName()` と同じで、「持っているものを見せてもらう」という意味。
- `alice.GetTool<Shovel>()` は alice に「シャベル持ってる？ 持ってたら見せて」と聞いている。持っていればそのポインタが返り、なければ `NULL` が返る。持ち主は変わらない
- 道具を渡す操作は、`Worker` のリストにポインタを入れること。こちらは持ち主が変わる
- `Worker` のリストは `Tool*` なので、外からは「どれが `Shovel` か」がわからない。それを型で探して取り出すのが `GetTool`
- 使う場面: `Workshop` が登録を受けるかどうかの判定（その道具を持っているか）と、`Worker` が自分の道具を使うとき
