### 疑問 2: 変数定義を 1 行で書くべきかどうかの基準
最初の理解: `Position` の `x, y, z` は変数として三位一体感が強いが、`Statistic` の `level`, `exp` は一体感が薄いから、別で定義するほうがいいのではないか。

答え: この感覚は合っている。今の書き方（`int x, y, z;` は 1 行、`level` と `exp` は別の行）のままでいい。
- 言語上はどちらでも正しく、動作も同じ。スタイルの話
- 既定は 1 行に 1 つ（C++ Core Guidelines の ES.10）。理由は 3 つ
  - `int* a, b;` は `a` だけがポインタで、`b` はただの `int` になる
  - 変数ごとにコメントや初期値を付けやすい
  - 後で 1 つだけ型を変えたり消したりするとき、変更が 1 行で済む
- まとめてよいのは、型が同じで、意味も 1 組になっていて、片方だけ変わることがないもの。`x, y, z` はこの典型
- `level` と `exp` は型が同じでも別々の概念（`exp` だけ後で `long` にしたくなるかもしれない）
- ポインタや参照が混ざるときは必ず分ける

> 1 つだけ型やコメントを変えたくなる可能性があるなら分ける。

最後の自分の言語化:
> なるほど、じゃあこのままでいいか

### 疑問 3: `size_t` 使いたいとき何 include すればいいんだっけ

- `<cstddef>` で確実に使えるのは `std::size_t`。`std::` なしの `size_t` も多くの環境で通るが、保証されていない
- `<vector>` や `<string>` を include しているとたまたま通ることがある。それに頼らず、使うファイルで `<cstddef>` を書く

### 疑問 4: `Tool &` を vector に持たせようとしたらエラーになった。なんでだろう
最初の理解: `Tool` のリファレンスを持たせた方がシンプルに扱えそう。エラーメッセージを見る感じ、vector のテンプレート的に pointer しか入れられない？

答え: vector に参照は入れられない。「ポインタしか入れられない」のではなく、「オブジェクトなら何でも入るが、参照はオブジェクトではない」。
- vector は要素へのポインタ（`Tool &*` にあたるもの）を内部で使う。参照へのポインタは C++ に存在しないので、テンプレートの中でエラーになる
- 参照は、あとから別のものを指すように変えられない。vector は要素を代入で動かしたり消したりするので、これとも合わない
- 道具は `std::vector<Tool *> tools;` で持つ
- ポインタは S2 の表とも合う。`Worker` と `Tool` は aggregation で、道具は渡したり取り上げたりする。「持っていない状態」や「持ち主が変わる」を表せるのはポインタ。`Worker` は道具を所有しないので、destructor で `delete` はしない

（確認の発言なし）

### 疑問 5: 抽象クラスの定義の仕方ってどんなんだっけ
最初の理解: 確かコンストラクタの作りが特殊だった気がする。全部 private にするんだっけか。

答え: コンストラクタは特殊ではない。純粋仮想関数（`= 0` をつけた virtual 関数）を 1 つ以上持つと、そのクラスは抽象クラスになる。

```cpp
class Tool
{
public:
    virtual ~Tool() {}
    virtual void use() = 0;  // 純粋仮想関数。これがあると Tool は抽象クラス
};
```

- `Tool t;` や `new Tool()` がコンパイルエラーになる。`Tool *` や `Tool &` は使える
- `Shovel` が `use()` を実装すると、`Shovel` は実体を作れる。実装しないと `Shovel` も抽象クラスのまま
- 「全部 private にする」は別の技法。コンストラクタを private にすると外から作れなくなるが、派生クラスからも呼べなくなるので、継承が使えなくなる

最後の自分の言語化:
> あー、それだ。純粋仮想関数を一つでも持っていれば抽象クラスなんだ。

### 疑問 6: destructor に virtual をつける理由と、vtable がなんの関係があるのか
最初の理解: 確か vtable が絡んでいて、これをつけないと派生クラスの削除時に抽象クラスの destructor が呼ばれない、みたいなのがあった気がする。vtable がなんの関係があるのかわからないのと、理解があっている自信がない。

答え: 向きが逆。virtual をつけないと呼ばれないのは、基底クラス（`Tool`）ではなく派生クラス（`Shovel`）の destructor。

```cpp
Tool *t = new Shovel();
delete t;
```

| `~Tool()` | 呼ばれる destructor |
|---|---|
| virtual なし | `~Tool()` だけ。`~Shovel()` は呼ばれない |
| virtual あり | `~Shovel()` → `~Tool()` の順に両方 |

- virtual なしは規格上は未定義動作。多くの環境で表のとおりになり、`Shovel` 側の後始末が抜ける
- 問題になるのは、基底クラスのポインタ経由で `delete` するときだけ。`Shovel s;` や `Shovel *` 経由の `delete` なら、virtual がなくても両方呼ばれる
- `delete t` のとき、コンパイラが知っているのは `t` の型が `Tool *` だということだけ。virtual なしだと、型だけを見てコンパイル時に「`~Tool()` を呼ぶ」と決めてしまう
- virtual ありだと、実行時にオブジェクトの vptr をたどって vtable の destructor の欄を見る。`new Shovel()` で作ったオブジェクトの vptr は `Shovel` の vtable を指すので、`~Shovel()` が呼ばれる
- `~Shovel()` の本体が終わると `~Tool()` が自動で呼ばれる。これは virtual と関係ない、destructor の通常の動き
- `t->use()` で `Shovel::use()` が呼ばれるのも同じ仕組み。destructor も、vtable に欄を持つ virtual 関数の 1 つにすぎない

> virtual は「ポインタの型ではなく、オブジェクトの本当の型で関数を選ぶ」ための印。destructor につけないと、`Tool *` 経由の `delete` で `~Shovel()` が選ばれない。

最後の自分の言語化:
> ああ、逆か。
> virtualを持つクラスが生成されるとき、vtableという表が一緒に作られて、virtual関数の実態のアドレスを持つ。クラスのインスタンスが生成されると、各インスタンスは自分のオブジェクトのvtableのアドレスを持ち、virtual関数を使用するときにはそのアドレスを辿って関数の実態にアクセスする

> なるほど、コンパイル時にvtableが作られるのか。2は自分の表現が悪かっただけで、イメージとは一致している。

（vtable が作られるのはコンパイル時で、単位はクラス。`Shovel` を 100 個作っても vtable は 1 つで、100 個のインスタンスの vptr が同じ表を指す）
